# 01-架构与依赖规则

## 一、架构风格

- **架构**：DDD + 六边形架构
- **分层顺序**：types → domain → api → application → adapter → infrastructure → starter
- **核心原则**：领域层不依赖应用层和基础设施层，通过依赖倒置解耦

## 二、依赖规则

### 2.1 内部依赖

```
types层 ──────> shared-types
domain层 ─────> shared-domain + xxx-types
api层 ────────> shared-api + xxx-types
application层 ─> xxx-api + xxx-domain + shared-*starter
adapter层 ─────> xxx-api + xxx-application
infrastructure层 -> xxx-domain + shared-*starter
starter层 ─────> xxx-adapter + xxx-infrastructure
```

### 2.2 跨服务依赖

- customer-service → business-core-api
- file-service → business-core-api
- integration-service → business-core-api

## 三、禁止规则

- ❌ domain层禁止依赖application/infrastructure层
- ❌ api层禁止依赖application/infrastructure层
- ❌ 禁止跨服务依赖非API模块
- ❌ 禁止循环依赖
- ❌ domain层禁止依赖除lombok外的外部库

## 四、模块划分

- `xxx-types`：领域原语（仅ID类型）
- `xxx-domain`：实体、值对象、聚合根、领域服务、SPI接口
- `xxx-api`：DTO、Command、Query、对外接口
- `xxx-application`：应用服务、流程编排
- `xxx-adapter`：Controller、DTO转换
- `xxx-infrastructure`：Repository实现、数据访问
- `xxx-starter`：启动类、打包入口
