# 08-错误码规范

## 一、错误码格式

错误码为 **5 位纯数字**，格式：`XYYZZ`

| 位段 | 含义 | 说明 |
|------|------|------|
| 第 1 位 X | 模块类别 | 0=通用, 1=公共基础, 2=业务核心, 3=业务服务 |
| 第 2-3 位 YY | 模块编号 | 见下方码段分配表 |
| 第 4-5 位 ZZ | 错误序号 | 模块内自增，01-99 |

## 二、码段分配表

### 通用码段（0XXXX）

| 码段 | 模块 | 说明 |
|------|------|------|
| 00000 | - | 操作成功 |
| 00001-00099 | shared-exception | 通用错误（HTTP 4xx/5xx 映射） |

### 公共基础模块（1XXXX）

| 码段 | 模块 |
|------|------|
| 10001-10099 | shared-exception（通用错误） |
| 11001-11099 | shared-types |
| 12001-12099 | shared-domain |
| 13001-13099 | shared-cache-starter |
| 14001-14099 | shared-id-starter |
| 15001-15099 | shared-event-starter |
| 16001-16099 | shared-logging-starter |
| 17001-17099 | shared-web-starter |
| 18001-18099 | shared-client-starter |
| 19001-19099 | shared-pdf-starter |

### 业务核心模块（2XXXX）

| 码段 | 模块 |
|------|------|
| 20001-20099 | business-core-domain |
| 21001-21099 | business-core-application |
| 22001-22099 | business-core-infrastructure |

### 业务服务模块（3XXXX）

| 码段 | 模块 |
|------|------|
| 30001-30099 | approval-service |
| 31001-31099 | file-service |
| 32001-32099 | integration-service |
| 33001-33099 | annuity-service |

## 三、消息规范

- ✅ 消息内容使用纯文本，**禁止使用 `{}` 占位符**
- ✅ 消息应描述错误本质，便于用户理解
- ✅ 动态上下文通过 `BaseException.withUserDetail()` / `withLogDetail()` / `withContext()` 附加
- ❌ 禁止在消息中嵌入变量占位符（如 `"用户{}不存在"`）
- ❌ 禁止在消息中使用方括号前缀（如 `"[实体不存在]{}"`）

**正确示例**：
```java
ENTITY_NOT_FOUND("12001", "实体不存在"),
INVALID_DATA("12002", "数据校验失败"),
```

**错误示例**：
```java
ENTITY_NOT_FOUND("12001", "[实体不存在]{}"),  // 禁止方括号前缀和占位符
INVALID_DATA("12002", "[数据有误]{用户ID为空}"),  // 禁止嵌入变量
```

## 四、错误码唯一性

- ✅ 每个 code 值全局唯一，不允许跨枚举重复
- ✅ 同一枚举内各常量的 code 必须不同
- ❌ 禁止不同语义的错误共用同一 code

## 五、HTTP 状态码映射

| 错误码范围 | HTTP 状态 | 异常类型 |
|------------|-----------|----------|
| 00001-00099（4xx 类） | 400/401/403/404/405/429 | BusinessException |
| 00001-00099（5xx 类） | 500 | SystemException |
| 1xxxx-3xxxx | 500（默认） | 按异常类型决定 |

> DomainException 和 BusinessException 的 HTTP 状态由 GlobalExceptionHandler 根据 ErrorDefinition 的 code 段决定。

## 六、枚举命名规范

| 类型 | 命名模式 | 示例 |
|------|----------|------|
| 错误码枚举 | 模块名 + ErrorCode(s) | `SharedDomainErrorCode`、`FileErrorCodes` |
| 枚举常量 | 大写下划线 | `ENTITY_NOT_FOUND`、`ID_GEN_ERROR` |

## 七、使用约束

- ✅ 所有自定义异常必须携带 `ErrorDefinition`，禁止裸抛 `RuntimeException`
- ✅ 错误码定义在各自模块的 `errorcode` 包中
- ✅ 公共错误码（通用 HTTP 错误）定义在 `CommonError` 中
- ❌ 禁止在 domain 层抛出框架异常（如 Spring/MyBatis 异常），必须封装为 `DomainException`/`BusinessException`/`SystemException`
