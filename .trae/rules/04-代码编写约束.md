# 04-代码编写约束

## 一、CQE模式约束
- ApplicationService接口入参只能是CQE对象（Command/Query/Event）
- Command命名：XXXCommand（写操作），Query命名：XXXQuery（读操作），Event命名：XXXEvent
- 不同语意使用不同CQE对象，禁止复用

## 二、API层约束
- 所有的API必须现在API层定义接口
- API接口必须使用 `@HttpExchange` 注解标记，方法使用 `@GetExchange`/`@PostExchange`，例如：
```java
@HttpExchange("/order")
public interface OrderApi {
    @GetExchange("/list")
    ApiResult<List<OrderResponse>> list(@Valid @RequestBody OrderQuery query);
}
```
- 不得使用GET和POST之外的其他请求类型
- 请求体使用 `@RequestBody` + `@Valid`，返回体统一 `ApiResult<T>`
- API接口定义在 `xxx-api` 模块中，只定义协议，不包含实现逻辑
- API接口命名：业务名称 + Api（如 OrderApi）
- 必须定义请求体DTO（XXXRequest）和返回体DTO（XXXResponse）

## 三、Adapter层约束
- Adapter必须实现API层定义的接口并标注 `@RestController`，例如：
```java
@RestController
@AllArgsConstructor
public class OrderController implements OrderApi {
    private final OrderService orderService;
    private final OrderConverter orderConverter;

    @Override
    public ApiResult<List<OrderResponse>> list(@Valid @RequestBody OrderQuery query) {
        return orderConverter.toResponse(orderService.list(query), orderConverter::to.list(query));
    }
}
```
- 绝对不允许在Adapter层直接定义API
- 通过构造函数注入依赖（应用服务、转换器）
- 请求体DTO → 领域Command/DTO：通过Converter/Mapper完成
- 领域DTO → 返回体DTO：通过Converter/Mapper完成
- 转换必须通过MapStruct Converter，禁止在Adapter中直接转换或编写转换逻辑
- 禁止在Adapter中编写业务逻辑、禁止直接操作Entity或DO

## 四、应用层约束
- ApplicationService标注 `@Service`，管理事务边界（@Transactional）
- 编排业务流程，不包含业务规则，通过构造函数注入依赖

## 五、基础设施层约束
- Repository实现必须在save方法中发布领域事件
- Data Converter负责Entity与DO转换
- 使用MyBatis-Flex进行数据库操作
- 禁止在Repository实现中编写业务逻辑

## 六、异常体系约束
- Domain层规则校验失败抛 `DomainException`
- 业务流程异常抛 `BusinessException`，系统错误抛 `SystemException`
- 禁止使用RuntimeException代替自定义异常
- 错误码使用 `ErrorDefinition` 定义

## 七、版本管理约束
- 禁止手动修改Version值，更新通过 `markUpdated()` 自动递增

## 八、DTO转换约束
- 所有DTO转换必须通过MapStruct Converter/Mapper完成
- MapStruct Mapper标注 `@Mapper(componentModel = "spring")`
- 禁止在Controller/Adapter中直接转换DTO

## 九、pom.xml配置约束
- 每新增一个服务模块，必须在父级项目的`pom.xml`中添加模块依赖
- 在父级项目的`pom.xml`中 `dependencyManagement` 部分的 `<!-- 2nd Dependencies-->` 部分添加 `xxx-api` 依赖, 例如：
  ```xml
  <dependency>
    <groupId>com.example</groupId>
    <artifactId>xxx-api</artifactId>
    <version>${project.version}</version>
  </dependency>
  ```
- 在新服务模块的`pom.xml`中 `dependenciesManagement` 部分添加 `xxx-types`, `xxx-domain`, `xxx-application`, `xxx-adapter`, `xxx-infrastructure` 依赖, 例如：
  ```xml
  <dependency>
    <groupId>com.example</groupId>
    <artifactId>xxx-types</artifactId>
    <version>${project.version}</version>
  </dependency>
  ```
- 引入新的依赖包时，需要在父级项目的 `pom.xml` 的 `properties` 部分添加 `xxx.version` 属性, 例如：
```xml
<xxx.version>1.0.0</xxx.version>
```
然后在 `dependenciesManagement` 部分引用 `xxx.version` 属性，例如：

  ```xml
  <dependency>
    <groupId>yyyy.zzzz</groupId>
    <artifactId>xxxx</artifactId>
    <version>${xxx.version}</version>
  </dependency>
  ```

## 十、禁止规则
- ❌ 禁止在Controller/Adapter中直接写业务逻辑
- ❌ 禁止在Service中混合数据访问逻辑
- ❌ 禁止使用业务DTO作为数据库映射对象
- ❌ 禁止在Service中手动发布领域事件
- ❌ 禁止直接修改Entity的createdBy、createdAt字段
- ❌ 禁止在API层接口定义中包含实现逻辑
- ❌ 禁止在Adapter中直接转换DTO，必须通过Converter/Mapper
