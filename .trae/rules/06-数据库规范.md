# 06-数据库规范

## 一、双数据库支持
- MySQL：各infrastructure模块包含 `schema-mysql.sql`
- PostgreSQL：各infrastructure模块包含 `schema-pg.sql`

## 二、表命名规范
| 对象类型 | 命名模式 | 示例 |
|----------|----------|------|
| 主表 | t_业务模块_业务名称 | t_business_application |
| 明细表 | t_业务模块_业务名称_detail | t_business_application_detail |
| 关联表 | t_业务模块_关联表名称 | t_business_application_batch |

## 三、字段命名规范
| 字段类型 | 命名模式 | 示例 |
|----------|----------|------|
| ID字段 | id | id |
| 业务编号 | xxx_no | acceptance_no |
| 状态字段 | xxx_status | application_status |
| 时间字段 | xxx_time | create_time、update_time |
| 删除标志 | deleted | deleted |
| 版本号 | version | version |

## 四、字段类型规范
| Java类型 | MySQL类型 | PostgreSQL类型 |
|----------|-----------|----------------|
| Long | BIGINT | BIGINT |
| String(varchar) | VARCHAR(255) | VARCHAR(255) |
| String(text) | TEXT | TEXT |
| LocalDateTime | DATETIME | TIMESTAMP |
| Integer | INT | INT |
| BigDecimal | DECIMAL(18,4) | DECIMAL(18,4) |
| Boolean | TINYINT(1) | BOOLEAN |

## 五、主键规范
- ✅ 主键字段名：`id`
- ✅ 主键类型：`BIGINT`
- ✅ 主键生成策略：使用 `shared-id-starter` 生成
- ❌ 禁止使用自增主键（AUTO_INCREMENT）

## 六、通用字段规范
所有业务表必须包含以下字段：
| 字段名 | 类型 | 说明 |
|--------|------|------|
| id | BIGINT | 主键 |
| created_by | VARCHAR(64) | 创建人 |
| created_time | DATETIME/TIMESTAMP | 创建时间 |
| updated_by | VARCHAR(64) | 更新人 |
| updated_time | DATETIME/TIMESTAMP | 更新时间 |
| deleted | TINYINT/BOOLEAN | 删除标志（0未删除，1已删除） |
| version | INT | 乐观锁版本号 |

## 七、索引规范
- ✅ 主键必须创建索引（聚簇索引）
- ✅ 业务唯一字段必须创建唯一索引，命名：`uk_表名_字段名`
- ✅ 常用查询条件字段应创建索引，命名：`idx_表名_字段名`
- ✅ 多字段查询条件应创建联合索引，命名：`idx_表名_字段1_字段2`

## 八、SQL编写规范
- ✅ 使用MyBatis-Flex的QueryWrapper构建查询
- ❌ 禁止手写SQL字符串拼接
- ✅ 使用参数化查询，防止SQL注入
- ✅ 查询必须包含删除标志过滤：`deleted = 0`
- ❌ 禁止使用SELECT *，只查询需要的字段

## 九、DO实体规范
- ✅ DO类命名：业务名称 + DO（如ApplicationDO）
- ✅ 字段名使用驼峰命名法（与数据库字段映射）
- ✅ 使用Lombok注解（@Data）
- ✅ 使用MyBatis-Flex注解定义表映射（@Table、@Column、@Id）
